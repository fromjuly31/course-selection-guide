# Supabase 학교 편제표 연동

이 폴더의 `schema.sql`은 학교 목록, 관리자·담당 교사 권한, 학교별 편제표를 만듭니다. 공통 과목 설명 DB(`data/database.json`)는 기존처럼 GitHub Pages에서 읽고, 학교별 편제표만 Supabase에서 읽고 씁니다.

## 1. Supabase 프로젝트 준비

1. Supabase에서 새 프로젝트를 만듭니다.
2. **SQL Editor**에서 `schema.sql` 전체를 실행합니다.
3. **Authentication > Users**에서 관리자 계정과 담당 교사 공용 계정을 각각 하나씩 생성합니다.
4. 두 계정의 User UUID를 복사하고 SQL Editor에서 역할을 연결합니다.

```sql
insert into public.platform_users (user_id, role) values
  ('관리자-USER-UUID', 'admin'),
  ('담당교사-USER-UUID', 'teacher');
```

- `admin`: 이메일·비밀번호로 로그인하며 새 등록, 기존 편제표 수정·삭제 가능
- `teacher`: 화면에서는 공용 관리 비밀번호만 입력하며 편제표 등록과 같은 학교·입학년도의 새 파일 교체 가능

## 2. 웹 프로젝트 연결

Supabase의 **Project URL**과 **Publishable key**를 확인한 뒤 루트의 `supabase-config.js`에 입력합니다.

```js
window.SUPABASE_CONFIG = {
  url: "https://YOUR_PROJECT.supabase.co",
  publishableKey: "sb_publishable_...",
  teacherEmail: "teacher-access@example.com"
};
```

`teacherEmail`에는 담당 교사 공용 계정의 이메일을 입력합니다. 화면에는 이 이메일이 표시되지 않고 담당 교사는 비밀번호만 입력합니다. `service_role` 또는 secret key는 브라우저 파일이나 GitHub에 절대로 넣지 않습니다. Publishable key만 사용하며 실제 읽기·쓰기 권한은 `schema.sql`의 RLS 정책이 제한합니다.

## 3. 학교 편제표 등록

1. 웹사이트의 **데이터 연동** 탭을 엽니다.
2. 현재 1·2·3학년에 해당하는 2026·2025·2024학년도 신입생 3개년 편제표 파일을 각각 준비합니다.
3. **직접 등록** 또는 **신입생 편제표 업로드**를 누르면 먼저 `teacherEmail`로 지정한 Supabase Auth 계정의 등록 비밀번호만 확인합니다.
4. 비밀번호 확인이 끝난 다음 화면에서 지역과 학교명을 입력합니다. 동일한 계정·지역·학교명으로 임시저장한 편제표가 있으면 가장 최근 저장본을 자동으로 불러옵니다.
5. 임시저장본이 없고 업로드를 선택한 경우 파일 선택 창이 열립니다. 세 파일을 한꺼번에 선택하면 플랫폼이 교과군·과목 유형·학년·학기·옵션·선택 수 머리글과 `택 N` 표시를 찾아 분석합니다.
6. 편집 화면 아래에서 **임시저장**을 누르면 입력이 덜 끝난 상태도 비공개 작업본으로 저장됩니다. **편제표 등록**을 누르면 현재 선택한 입학년도의 편제표가 학생 시뮬레이션에 공개되고, 편집 화면 전체도 최신 작업본으로 함께 저장되어 다음 접속 때 다시 불러올 수 있습니다.

담당 교사 등록 인증은 편제표 저장 또는 편집 취소 시 자동으로 종료됩니다. 다음 직접 등록·업로드 작업을 시작할 때 비밀번호를 다시 확인합니다. 관리자 로그인 세션은 우측 상단에서 직접 로그아웃할 때까지 유지됩니다.

임시저장 기능만 추가할 때는 Supabase Dashboard의 **SQL Editor → New query**에서 `supabase/install-curriculum-drafts.sql` 전체를 한 번 실행하면 됩니다. 전체 구조를 처음 설치하는 경우에는 `supabase/schema.sql`을 실행하세요. 앱은 `curriculum_drafts`가 설치된 즉시 Supabase 원격 임시저장을 우선 사용하며, 등록 비밀번호 원문은 임시저장 테이블에 기록하지 않습니다.

기존에 설치한 프로젝트에서 담당 교사가 이미 등록된 학교·입학년도의 편제표를 교체할 때는 `supabase/install-teacher-curriculum-publish.sql`도 SQL Editor에서 한 번 실행하세요. 이전의 관리자 전용 수정 정책이 남아 있으면 수정 요청이 0건으로 끝날 수 있으며, 최신 앱은 이 경우 성공으로 표시하지 않고 정책 적용이 필요하다는 오류를 보여 줍니다.

관리자는 편제표 등록 카드 우측 상단의 작은 **관리자 로그인** 버튼에서 이메일·비밀번호로 로그인합니다. 로그인 후 연동 학교와 입학년도를 선택하면 해당 편제표를 편집 화면으로 열어 수정하거나, 입학년도별 편제표 또는 학교의 전체 연동 데이터를 삭제할 수 있습니다.

한 학교·한 입학년도에는 하나의 편제표가 저장됩니다. 같은 학교·입학년도의 파일을 다시 등록하거나 관리자 편집 화면에서 저장하면 기존 내용이 교체되며, 삭제는 관리자만 할 수 있습니다. 학생은 학교를 고른 뒤 그 학교에 공개된 입학년도 목록에서 자신의 입학년도를 선택하며, 선택한 연도의 편제표만 연동됩니다.

학교 목록의 입학년도는 `curricula.admission_year`를 학교별로 묶어 최신순으로 제공합니다. 연도를 학교 행에 중복 저장하지 않으므로 편제표를 등록하거나 삭제하면 목록에도 자동으로 반영됩니다.

## 편제표 열 규칙

| 열 | 값 |
|---|---|
| 학년 | `1`, `2`, `3` |
| 학기 | `1`, `2` |
| 구분 | `공통` 또는 `선택` |
| 옵션 | 선택과목은 `옵션 1`~`옵션 10` 중 하나를 입력 |
| 선택 수 | 해당 옵션에서 골라야 하는 개수를 `1`~`10` 사이 정수로 입력 |
| 과목명 | 학년·학기별 공통 또는 같은 옵션의 과목을 한 행에 쉼표(`,`)로 구분해 입력 |

학년·학기별 공통 과목은 한 행만 사용하고, 같은 학년·학기·옵션도 한 행만 사용합니다. 선택 수는 그 옵션에 입력한 과목 수보다 클 수 없습니다. 공통 과목은 자동 이수 과목으로 표시되며, 옵션 과목은 시뮬레이션에서 1학년부터 3학년까지 `택 N` 규칙에 따라 순서대로 선택할 수 있습니다.
